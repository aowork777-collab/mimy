# mimy. 動作確認チェックリスト

検証用のキャスト1人、利用者2人、管理者1人を用意します。同時操作はブラウザーのプロファイルを分け、通話は別々の端末で確認します。決済にはStripeサンドボックスを使います。結果は公開バージョン、端末とブラウザー、実施日時、予約ID、合否を記録します。

## 先に確認する項目

| ID | 確認項目 | 操作 | 合格条件 |
| --- | --- | --- | --- |
| A01 | 公開URL | スマホとPCの未ログイン状態でトップ、ログイン、キャスト詳細を開く | 公開URLと各ページが表示され、ログイン画面への導線を使える |
| A02 | メール認証 | 新規登録し、受信したメールのリンクを開いてログインする。別途、再設定メールからパスワードを変える | 確認前のログインは拒否される。確認後と再設定後はログインでき、旧パスワードは拒否される |
| A03 | 既存データと権限 | 既存アカウントで再ログインし、キャストと管理者の画面を確認する。利用者でも管理機能へのアクセスを試す | 承認済みキャストと申請状態、既存の予約日時・履歴を引き継ぐ。管理画面と管理APIは管理者だけが使える |
| S01 | SNSの表示・遷移 | 4サービスのIDと公式URLを混ぜて保存する。プロフィールを再読込し、各アイコンを押す | 対応する4種類のロゴが表示され、それぞれ正しいプロフィールが別タブで開く。キーボードで選べ、読み上げでサービス名が分かる |
| S02 | SNSの削除と入力検証 | 1欄の値を消して保存する。別サイトのURLまたは不正なIDも入力してみる | 消したSNSのアイコンだけが消える。不正な入力はエラーになり、保存済みのリンクは維持される |
| B01 | シフトの時間範囲 | 翌日20:00〜22:00を登録し、利用者で30分と60分を切り替える。別日に23:30〜翌01:00も登録する | 30分は20:00・20:30・21:00・21:30、60分は20:00・20:30・21:00を選べる。翌日の時刻も日本時間の正しい日付で表示される |
| B02 | 過去・重複・受付停止 | 過去や重複するシフトを登録する。予約が1件ある状態で新規受付を止めてから再開する | 過去・重複の登録が拒否される。受付停止で空き枠が消え、済んだ予約は維持される。再開後は空いた時間だけが戻る |
| B03 | 二重予約 | 2人の利用者が、同じキャストの20:00〜21:00と20:30〜21:00を同時に仮押さえする。別途、同じ利用者で同時間帯の別キャストも試す | 各競合で成立は1件のみ。20:00〜20:30と20:30〜21:00のように境界だけが接する予約は両方成立する |
| B04 | 仮押さえの取消・期限 | 支払い前に取り消す。別の予約はCheckoutを開かずに期限を待ち、空き枠を再読込する | 在庫が解放され、同じ時間を再予約できる。期限切れ予約は決済に進めない |
| P01 | 料金から決済完了まで | 新人・人気の30分と60分の表示額を確認し、シフト開始より後の枠でStripeテスト決済を1件行う | 料金は新人1,990円・3,980円、人気2,990円・5,980円。Checkoutの金額、予約開始時刻、予約履歴・購入履歴が一致し、支払い後は予約が確定する |
| P02 | 決済の中断・通知の再送 | テストカードで失敗を再現する。Checkoutから戻るケースとCheckoutの取消・失効も試す。成功イベントはStripeから再送する | 支払いに失敗した予約は確定しない。取消・期限の処理後に枠が解放され、通知を再送しても購入履歴は1件のまま |
| C01 | 予約時刻と通話終了 | 開始前、開始後、終了後に2端末で参加する。通話中は片方の画面状態の取得を止めて、終了時刻を待つ | 開始前と第三者は参加不可。予約した時刻に音声と映像がつながり、終了時刻にサーバーから両者が退出し再参加できない |

通話の実機確認は、終了管理Workerの接続と、既知のWorker通信エラーの修正後に行います。[通話の確認条件](PRODUCTION.md#現在の運用)

## 公開サイトで一巡する項目

| ID | 確認項目 | 操作 | 合格条件 |
| --- | --- | --- | --- |
| M01 | メッセージ・権限 | 予約当事者2人で送受信し、別アカウントで履歴取得を試す。検証環境では連続送信も試す | 当事者だけが読める。送信上限に達するとリクエストが制限される |
| M02 | 管理者による利用停止 | テスト利用者を停止して予約・送信・通話を試し、管理画面で登録メール・予約・購入履歴を確認してから解除する | 停止中の操作が拒否され、管理者は履歴を確認できる。解除後に利用を再開できる |
| M03 | 推し・限定日記・写真 | 推す前後で一覧と日記を開き、写真付きの限定日記の画像URLを未承認の利用者でも開く。テスト写真の配信データの位置情報も調べる | 推したキャストが一覧上部に出る。キャストには表示名と人数が見える。限定の本文・写真は対象者だけに配信され、位置情報は除去される |
| U01 | スマホでの操作 | iPhoneのSafariとAndroidのChromeで、プロフィール・SNS・シフト入力・予約画面を操作する | 横スクロールやボタンの重なりがなく、入力、タップ、画面遷移ができる |

ローカルの自動テストは予約競合、旧データの移行、SNS入力、権限、Webhookなどを検証します。上の表で公開環境と実機の状態を確認します。[自動テストの実行手順](developer-guide/local-development.md#2-テストから確認する)
