# 本番化の仕様

## 外部契約が必要なもの

1. サービス実態に対応する決済事業者の審査・契約。広告、会話内容、禁止事項を提示する。
2. 通話サービスの利用条件確認。LINEは通話イベント・自動切断を前提にしない。
3. 通知プロバイダー、送信ドメイン・LINE公式アカウント。
4. 事業者情報、正式規約、キャンセル規定、保存・削除方針、キャスト契約。

## 本番の認可とデータ分離

現在は owner 単位の隔離されたsandbox。本番ではユーザー、スタッフ、キャストと配属情報を別表で管理し、サーバーがロールを取得する。画面のタブ・POSTのroleは認可に使わない。利用者は自分の予約だけ、キャストは自分の割当予約だけ、運営は権限を持つ操作だけ実行可能とする。管理者付与は運営が行い、初回ログイン者へ自動付与しない。

予約在庫を cast + 開始終了範囲で全ユーザー共有にする。現在の固定1時間枠と最大60分ならcast+slotの一意制約、可変時間枠へ変更するなら重複区間を原子的に確保する。期限切れhold解放はDB処理で保証する。

## 決済アダプタ

- createCheckout(bookingId, serverCalculatedAmount, idempotencyKey)
- verifyWebhook(rawBody, signature)
- refund(paymentId, amount, idempotencyKey)

金額はサーバーの予約スナップショットから取得。webhookイベントIDを一意保存し、決済ID、金額、通貨、予約、capture成功を検証。画面遷移では予約を確定しない。仮押さえ解放後の決済成功は在庫再取得を試み、取得できなければ返金待ちへ。決済、予約、返金、通話状態は独立した表に分割する。現在のpayment文字列はテスト専用。

払い戻しは要求と確定を分け、外部プロバイダーの成功通知で確定。再送・重複・順序逆転をテスト。未知のイベントは状態を更新しない。

## 通話アダプタ

- createRoom(bookingId)
- issueParticipantToken(bookingId, authenticatedActorId, expiration)
- handleVerifiedCallEvent(event)
- terminateRoom(bookingId)

会議URLの公開は禁止。開始可能時間、担当者、決済確定を検証して短期トークン発行。サーバーで入退室と終了時刻を記録。両者接続開始を課金基準とするか固定予約枠とするか事前に規約と一致させる。再接続、タイムアウト、片側未接続、スマホ画面ロックを検証する。

## その他の残作業

- シフト編集・本人年齢審査・声のサンプル管理
- 報酬台帳（率スナップショット、調整履歴、送金確定）、運営承認
- outboxを用いた通知、送信失敗・再送管理
- rate limit、監視、アラート、バックアップ復元演習
- 利用停止・退会・データ削除・保存期限
- モーダルのフォーカストラップ等のアクセシビリティ改善
- 全実機E2Eと外部sandbox決済・通話検証

## 公開条件

上記接続および認可が完了するまで、所有者限定の検証用途のまま運用する。単に画面の「検証モード」を外して一般利用を開始しない。
