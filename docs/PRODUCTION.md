# 公開と本番決済の準備

## 現在の運用

公開サイトではメール認証とStripeサンドボックスを利用します。テスト決済の操作は確認済みです。本番キー・実決済・実返金・キャストへの送金は今後の対応です。通話はLiveKitに加えて、終了を管理する専用Workerの接続と実機確認が必要です。

通話の接続検証前に、[通話終了Workerを呼ぶコード](../lib/call-guard-client.ts)の `redirect: 'error'` を修正します。これは以前のStripe接続障害と同じく、Cloudflare Workersでサポートされない指定です。Stripeの通信と同様に `redirect: 'manual'` と応答ステータスの確認を組み合わせ、接続後は2端末で参加から終了までを確認します。

## ソースから公開サイトへ反映する

1. GitHubの対象コミットを確認し、型チェック・関連テスト・ビルドを実行します。
2. 同じソースをSitesへ同期してバージョンを保存します。Sitesのサイト設定で対象環境と環境変数を確認します。
3. デプロイが完了したら、公開URLで変更した機能を確認します。DB変更がある場合は適用結果も確認します。
4. 決済変更ではStripeのワークベンチでAPIログ・Webhook配送と、mimy.側の予約状態・購入履歴を確認します。

本体のコードと公開バージョンは個別に管理します。資料のみの更新はGitHubにpushすれば閲覧できます。[利用ツールと運用先](developer-guide/services.md)

## 実決済へ進む前に決めること

| 項目 | 準備すること |
| --- | --- |
| 支払いの対象と事業者設定 | Stripeの申請内容と提供するサービスを照合し、本番環境で使う決済手段を決める |
| 決済データと本番設定 | テストと本番のキー・Webhook・決済記録を分ける。現在のコードはテストキーとテストイベントを前提とするため、本番対応を実装する |
| 支払いと予約のずれ | 重複通知・失敗・期限切れ・利用停止と支払いが前後する場合に、予約を確定する条件と運営の照合手順を決める |
| キャンセル・返金 | 期限、返金額、担当者、履歴の記録と連絡方法を決め、失敗時の再試行も検証する |
| キャストへの報酬 | 取り分、振込時期、明細、取消・返金時の精算方法を決める |
| 公開運営 | 利用規約・プライバシー案内・事業者の連絡先を確定し、問い合わせ、障害時の調査、データ保全の担当を決める |

本番への切替前には、利用者・キャスト・管理者の3アカウントで予約から購入履歴まで確認し、決済成功、利用者取消、期限切れ、Webhook再送の各ケースをサンドボックスで再現します。[Stripeサンドボックスの手順](stripe-test-setup.md)
